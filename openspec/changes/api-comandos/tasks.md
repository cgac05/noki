# Tasks

Cada grupo es un punto de control: al terminarlo, `pnpm lint && pnpm lint:deps && pnpm test && pnpm test:integracion` deben estar en verde (Postgres y Redis de `infra/docker-compose.yml`); registrar resultados reales en `implementacion.md`. Escribir primero la prueba de cada comportamiento (`AGENTS.md` §12). Unitarias de rutas en `packages/adapters/in-http/test/` (con `fastify.inject` y la composición en memoria), unitarias de aplicación y adaptadores en `tests/unit/api/`, integración en `tests/integracion/` (design D13). Toda respuesta HTTP de las pruebas se valida con su esquema de `@noki/contracts`. Las pruebas existentes que usan `crearApi` se adaptan a su firma nueva conservando cada comprobación: no se borran, no se marcan `skip` ni se debilitan sus expectativas; registrar cada prueba adaptada en `implementacion.md`. No modificar archivos compartidos, `001_nucleo.sql`, `002_persistencia.sql` ni `apps/web`; si hace falta, detener la parte afectada (ver `handoff.md`). Los grupos 1–4 son el mínimo para la integración del Flujo A; desde la revisión 4 el grupo 7 ya no espera a nadie, porque `contratos-flujo-a` está en `main`.
