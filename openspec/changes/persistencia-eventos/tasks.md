# Tasks

Cada grupo es un punto de control: al terminarlo, `pnpm lint && pnpm lint:deps && pnpm test` deben estar en verde y, desde el grupo 1, también `pnpm test:integracion` (Postgres y Redis de `infra/docker-compose.yml`); registrar resultados reales en `implementacion.md`. Escribir primero la prueba de cada comportamiento (`AGENTS.md` §12). Unitarias en `tests/unit/persistencia/` e integración en `tests/integracion/` (design D11). Las pruebas existentes de `tests/unit/nucleo/` que usan contratos que cambian aquí (`AgendaPort.confirmar`, eventos de `RegistroIntentosMemoria`, `ConflictoVersion` de la agenda) se adaptan en la tarea que cambia el contrato (2.1, 3.1, 4.3), conservando cada comprobación de comportamiento: no se borran, no se marcan `skip` ni se debilitan sus expectativas; registrar en `implementacion.md` cada prueba adaptada y qué cambió. No modificar archivos compartidos, `001_nucleo.sql` ni `apps/web`; si hace falta, detener la parte afectada (ver `handoff.md`). Los grupos 1–3 son el mínimo que necesita `api-comandos`.
